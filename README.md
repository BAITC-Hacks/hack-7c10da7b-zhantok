# MusicEdu AI

MusicEdu AI — хакатонный MVP для HackAlem AI: ИИ-платформа для создания, улучшения и публикации практических задач в музыкальном образовании.

## Проблема

Бизнес, музыкальные школы и преподаватели часто формулируют практические задачи слишком кратко: не хватает целевой аудитории, материалов, критериев успеха и понятного результата. Из-за этого студенческим командам сложно подготовить качественное предложение.

## Решение

MusicEdu AI помогает превратить слабое описание в структурированную карточку задачи:

1. бизнес вводит черновик;
2. локальный ИИ-помощник задает уточняющие вопросы;
3. система генерирует редактируемую карточку;
4. задача получает прозрачный рейтинг готовности;
5. бизнес может улучшить и опубликовать задачу;
6. студенческие команды отправляют предложения;
7. бизнес вручную принимает или отклоняет предложения.

Автоматического назначения команд нет.

## Целевые пользователи

- представители бизнеса и образовательных организаций;
- преподаватели домбры, фортепиано и музыкальной теории;
- студенческие команды, которые хотят решать практические задачи;
- организаторы хакатонов и проектного обучения.

## Технологический стек

- Vite
- React
- JavaScript
- CSS
- localStorage
- локальные deterministic mock-функции вместо внешнего ИИ API

## Архитектура MVP

Приложение полностью frontend-only:

- нет backend;
- нет базы данных;
- состояние хранится в React state;
- важные демо-данные сохраняются в localStorage;
- логика ИИ имитируется локальными функциями:
  - `generateQuestions()`;
  - `generateTaskCard()`;
  - `calculateScore()`;
  - `improveTask()`.

## Локальный AI mock

В MVP не используется внешний ИИ API. Все ИИ-действия выполняются детерминированно внутри браузера.

### Формат входных данных

```json
{
  "title": "Помощник для регулярной практики домбры",
  "description": "Хочу помочь ученикам домбры больше заниматься дома.",
  "answers": [
    "Начинающие ученики домбры",
    "Есть упражнения и заметки преподавателя",
    "Нужен прототип помощника для практики",
    "Без регистрации и внешнего ИИ"
  ]
}
```

### Пример prompt

```text
Проанализируй слабое описание музыкальной задачи, задай уточняющие вопросы и подготовь структурированную карточку для студенческой команды.
```

### Формат выхода

```json
{
  "questions": [
    "Кто является целевой аудиторией?",
    "Какие учебные материалы или данные доступны?",
    "Какой результат должна обеспечить разработка?",
    "Какие есть ограничения?"
  ],
  "taskCard": {
    "title": "Помощник для регулярной практики домбры",
    "theme": "Домбра",
    "context": "Описание проблемы",
    "need": "Потребность",
    "targetUsers": "Целевая аудитория",
    "materials": "Данные / материалы",
    "expectedResult": "Ожидаемый результат",
    "successCriteria": "Критерии успеха",
    "constraints": "Ограничения",
    "interactionFormat": "Формат взаимодействия",
    "contact": "Контакт / обратная связь"
  }
}
```

### Обработка некорректного ответа

Так как текущий ИИ является локальным mock, приложение не получает невалидный JSON от внешней модели. Вместо этого:

- пустое название блокирует анализ;
- пустое описание блокирует анализ;
- для генерации карточки нужно ответить минимум на 3 вопроса;
- перед публикацией нужно заполнить название и контекст;
- перед публикацией нужно подтвердить: "Я проверил данные карточки и подтверждаю их";
- при пустых полях предложения показывается русское сообщение об ошибке.

## Формула рейтинга готовности

Рейтинг рассчитывается от 0 до 100. Каждое поле получает 0, частичный балл или полный балл в зависимости от заполненности и детализации.

| Критерий | Вес |
|---|---:|
| Контекст / потребность | 20 |
| Данные / материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт / обратная связь | 10 |
| **Итого** | **100** |

## Уровни готовности

| Рейтинг | Уровень |
|---|---|
| 0-39 | Черновик |
| 40-69 | В работе |
| 70-89 | Готово |
| 90-100 | Приоритетная задача |

Низкий рейтинг не блокирует публикацию.

## ИИ-уточнение

После черновика система задает 4 вопроса:

- Кто является целевой аудиторией?
- Какие учебные материалы или данные доступны?
- Какой результат должна обеспечить разработка?
- Какие есть ограничения?

Ответы пользователя попадают в редактируемую карточку задачи.

## Каталог

Публичный каталог показывает опубликованные задачи и сортирует их по рейтингу готовности от большего к меньшему. В карточке видны название, описание, целевая аудитория, рейтинг, уровень готовности и подробности.

В каталоге есть фильтры:

- Тема;
- Уровень готовности.

## Предложения команд

Студенческая команда открывает задачу в каталоге и заполняет предложение:

- название команды;
- идея решения;
- план реализации;
- предполагаемый срок;
- ссылка на прототип.

Предложение получает статус "Ожидает решения".

Бизнес вручную выбирает:

- "Принять";
- "Отклонить".

Статусы:

- Ожидает решения;
- Принято;
- Отклонено.

## Сценарий демонстрации

1. Открыть главную страницу.
2. Нажать "Создать задачу".
3. Оставить слабое описание: "Хочу помочь ученикам домбры больше заниматься дома."
4. Нажать "Проанализировать с ИИ".
5. Ответить минимум на 3 вопроса.
6. Нажать "Создать карточку задачи".
7. Показать низкий или средний рейтинг и прозрачную разбивку.
8. Нажать "Улучшить задачу с помощью ИИ".
9. Показать более подробную карточку и рост рейтинга.
10. Нажать "Опубликовать задачу".
11. Открыть каталог и показать сортировку по рейтингу.
12. Нажать "Подробнее" у задачи.
13. Отправить предложение команды.
14. Перейти в "Предложения".
15. Вручную нажать "Принять" или "Отклонить".

## Ограничения

MVP намеренно не реализует:

- backend;
- базу данных;
- регистрацию;
- сложную авторизацию;
- чат;
- уведомления;
- платежи;
- blockchain;
- мобильное приложение;
- распознавание звука;
- обучение ML-моделей;
- внешний ИИ API;
- автоматическое назначение команд.

Текущая ИИ-функциональность использует deterministic local mock logic для демонстрации хакатонного сценария и не обращается к внешним сервисам.
